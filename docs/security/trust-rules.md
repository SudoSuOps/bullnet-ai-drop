# Trust rules for site content

These are mandatory for every change to copy, content config or demos.

## Never
- Claim an NDA alone guarantees confidentiality
- Imply ENS proves real-world authority, device integrity or agent reliability
- Publish client information on a public chain by default
- Claim every deployment is offline or air-gapped
- Invent certifications, benchmarks, testimonials, partners or prices
- Guarantee investment results or availability
- Present example valuations as real client transactions
- Portray agents as licensed professionals or fiduciary decision-makers
- Describe proposed software as production-certified
- Portray BullNet as a brokerage, a fund or a token project
- Describe a vertical as available before it exists. Offered today: commercial real estate, and equipment and hardware acquisition (Hive Capital Markets)
- Describe BullNet as a lender, quote rates, or imply approval or terms. Financing comes from third-party lenders

## Always label which of these a claim is
| Label on the site | Meaning |
| --- | --- |
| Historical experience | The founder's prior CRE career. Approximate, not independently audited. |
| Existing infrastructure | Compute BullNet operates today. |
| Proposed capability | Designed, and validated per deployment before it is relied on. |
| Illustrative demonstration | Example data. Not a client, a transaction or a live service. |
| Design concept | Physical or visual concept. No specifications implied. |

## Status vocabulary (Defendable)
`MATHEMATICALLY VERIFIED`, `EVIDENCE SUPPORTED`, `INCONCLUSIVE`, `FAILED`, `REQUIRES HUMAN REVIEW`. Status is always written in words. Colour is added on top and is never the only signal.

## Public code
No credentials, wallet keys, private endpoints or internal Node addresses. No document upload on the public site. The intake form must not say a request was received unless an endpoint returned success.
